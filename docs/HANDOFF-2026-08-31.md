**LAN gateway (bigdog :4000)** — changed since the last handoff:

> The last two rows land with **PR #45**. Until it merges, `measurements.csv`
> still carries the superseded 42.3 and 45.9 — see the correction table below
> for why those were wrong.

The new engine wins every cell. Two standing caveats:

- **c=1 sits inside the noise.** Its anemll comparator is an 8-rep noise-floor
  study spanning 66.6–88.5 tok/s (a 33% spread) on an unchanged engine. The
  concurrency rows are the load-bearing ones.
- **This is not a single-variable A/B and cannot be made into one.** The
  speculator differs permanently: anemll MTP K=2 vs eugr DSpark nst=5, and nst<5
  is *rejected* by the checkpoint (`dspark_block_size: 5`). Read it as each
  engine at its own working depth.

## 3. Numbers the previous handoff published that are now WRONG

Four corrections, all evidence-backed. If you are working from the 08-30 page,
these are the rows to distrust:

| claim there | actual | why it was wrong |
|---|---|---|
| c=8 +20%, c=16 −17% ("scheduling cliff") | **+76%, +24%** | measured with kernel caches disabled — kernels were JIT-compiling *during* the run. Lower bounds; the cliff was an artefact. |
| 131K decode 42.3 (−49%) | **90.5 (+8%)** | harness mismatch: that run measured the driver's own filler prompt, the reference used `bench-miaai --prompt 131072`. DSpark acceptance is prompt-dependent, so it was never a comparison. |
| dense-prose 45.9, ratio 1.95× | **49.2, ratio 1.85×** | the "lost" prompt was in git history at `b078eb4`. The 1.95× was a *reconstruction's* ratio, not the real one. |
| KV 2,415,674 / 2.30x for both nst arms | **2,357,009 (2.25x)** and **2,405,070 (2.29x)** | that figure was arm 1's boot, carried into the sweep's tables. The mnbt=16384 cost is −50.5%, not −52% — conclusion unchanged. |

The superseded rows are relabeled in `measurements.csv`, never deleted.

## 4. Next steps

1. **Repoint or retire the `qwen3.8-27b` gateway route** (see §1). Smallest real
   breakage on the LAN right now.
2. **Run the LiteLLM cutover on any box that still needs it** — on bigdog it is
   done. `bash $HOME/litellm/cutover-to-systemd.sh` is idempotent.
3. Optional: `--kv-cache-dtype nvfp4_ds_mla` on this build, to remove the KV
   delta vs anemll — *if* the build supports it. Untested.
4. Optional: `max_num_seqs` above 16. Every c=16 row is at the cap, so the
   concurrency ceiling is a *setting*, not a measured limit.

## 5. Traps added to troubleshooting.md in this window

Readiness gates inline in `ExecStartPost=` pass `systemd-analyze verify` and
still fail at runtime (verify does not evaluate embedded shell); `StartLimit*`
are silently ignored under `[Service]`; a LiteLLM route can 500 while
`/v1/models` returns 200; reading `content` alone makes a working DSv4 reply
look like a failure (the budget goes to `reasoning_content`); an unquoted comma
in a CSV `notes` field is invisible to `csv.DictReader`; search git history
before declaring a prompt or artifact unrecoverable.
